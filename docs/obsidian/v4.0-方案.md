## 核心结论

### 为什么选 OpenAI Agents SDK

| 因素 | 评分 | 理由 |
|------|------|------|
| 渠道接入难度 | ⭐⭐⭐⭐⭐ | Runner.run() 是纯库调用，包装简单 |
| 多 Agent 手 | ⭐⭐⭐⭐⭐ | Handoff 是最干净的显式模式 |
| 持久化 | ⭐⭐⭐⭐ | SQLiteSession 够用 |
| Guardrails | ⭐⭐⭐⭐⭐ | 内建三阶 |
| 社区 | ⭐⭐⭐⭐ | 19k+ stars，OpenAI 官方维护 |

vs LangGraph（图太重）、CrewAI（一次性执行不适合对话）、Google ADK（绑 Google Cloud）、AutoGen（维护模式）、Claude SDK（锁 Claude）。

### 架构

```
渠道适配层 (Channel Adapter Layer)
  ├── FeishuAdapter
  └── Message Router (session 管理)
        │
OpenAI Agents SDK Runtime
  ├── Runner.run() / run_streamed()
  ├── Agent Chat ←→ Plan ←→ Executor
  ├── Guardrails (input/output)
  └── Tools (MCP / Custom)
```

### 与 Hermes 的传承关系

| Hermes 的功能 | 新方案处理 | 继承/放弃 |
|-------------|-----------|----------|
| WeChat/Feishu 适配器 | 复用设计 | ✅ 继承 |
| MCP 集成 | OpenAI SDK 支持 MCP tools | ✅ 继承范式 |
| 多 Agent 三段式 | 原生 handoff | ✅ 更干净 |
| Session 管理 | SQLiteSession 替代 | ✅ 更稳 |
| Hermes 核心代码 | 不再维护 | ❌ 放弃 |
| kanban-plugin | 不再需要 | ❌ 放弃 |
