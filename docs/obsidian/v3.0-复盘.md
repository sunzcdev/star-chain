# v3.0 — 复盘与多 Agent 协作方案思考

> 从「三段式 Kanban 流水线」到「多 Agent 协作系统」的思路转变。
> 这是从 Hermes Plugin 路线转向 OpenAI Agents SDK 路线的关键反思。

（完整内容见 Obsidian 原始笔记：`做/Hermes多模式切换改造/v3.0-复盘与多Agent协作方案思考.md`）

## 核心根因

我们把多 Agent 协作做成了权限管理，而需要的是通信协议。

| 维度 | 当前系统的假设 | 实际需要的 |
|------|-------------|----------|
| 核心关注 | 谁不能做什么（工具门控） | 谁做了什么，进展如何（可见性） |
| 角色关系 | 各干各的，互不打扰 | 互相依赖、接力、协作 |
| 状态传递 | 写 DB（异步，无通知） | 推送到上游 + 反馈（通信） |
| 用户位置 | 等用户问才汇报 | 主动告知进度 |
| 失败处理 | 静默失败 | 告警 + 回退路径 |

## 理论基础

- **Actor Model** — 每个 Agent 是一个 Actor，只通过消息通信
- **CSP** — Agent 通过命名通道收发消息
- **Petri Net** — 工作流状态机
- **Blackboard System** — 共享工作区

## 推荐协作模式：消息 + 黑板混合

Agent 间通过消息通道通信（推送、回问、结果报告）
Agent 通过共享工作区交换交付物（方案、代码、测试）
