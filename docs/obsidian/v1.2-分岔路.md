# v1.2 — 架构分岔路

> 给 OpenAI SDK 加通道 vs 给 Hermes 加多 Agent — 原始路线选择。

（完整内容见 Obsidian 原始笔记：`做/Hermes多模式切换改造/v1.2-架构分岔路-OpenAI_SDK_vs_Hermes.md`）

## 两条路

### 路线 A：给 OpenAI Agents SDK 加通道
```
OpenAI Agents SDK（多 Agent 能力）
  └─ 缺少：WeChat、Telegram、cron、MCP、记忆
  └─ 要加：通道层 + 调度层 + 记忆层
```

### 路线 B：给 Hermes 加多 Agent 协作
```
Hermes（通道/调度/MCP/记忆）
  └─ 缺少：原生多 Agent 编排
  └─ 要加：Agent 角色定义 + 工作流 DAG + 交付物传递
```

## 决策历程

1. **v1.2 (6/5)**：选路线 B → 给 Hermes 加多 Agent → 翻车
2. **v3.0 (6/7)**：复盘发现「权限思维」问题
3. **v4.0 (6/7)**：转向路线 A → OpenAI Agents SDK + 渠道层 → **这就是 StarChain**

## 关键权衡

| 维度 | A: OpenAI SDK + 通道 | B: Hermes + 多 Agent |
|------|---------------------|---------------------|
| 通道 | ❌ 要重写 | ✅ 已有 |
| 多 Agent 编排 | ✅ 原生 handoff | ⚠️ delegate_task 不够优雅 |
| 改造成本 | 中（写渠道层） | 高（重写多 Agent 层） |
| 模型锁定 | ⚠️ 仅 OpenAI-compatible | ✅ 任意 provider |
