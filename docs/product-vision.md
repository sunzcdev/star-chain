# StarChain 产品蓝图：多智能体 Coding Agent 平台

> **定位：** 一个多智能体协作的 Coding Agent 平台。
> 不仅是一个聊天机器人，而是一个拥有不同角色的 Agent 团队，协作完成编码任务。
> 对标 Claude Code / Codex / Cline / Hermes，但核心差异是多 Agent。

---

## 一、竞品格局

### 现状：市场全是"单 Agent"

```
产品           形式         架构         核心 Agent 数量
──────────────────────────────────────────────────────
Claude Code    CLI         单 Agent             1
Codex CLI      CLI         单 Agent             1
Cline          VS Code     单 Agent + 工具路由    1
Cursor         IDE         单 Agent + 工具路由    1
GitHub Copilot IDE         单 Agent             1
Gemini CLI     CLI         单 Agent             1
Hermes         IM/CLI      多 Profile 流水线     3 (Manager/Planner/Executor)
```

**共同点：** 无论界面是 CLI、IDE 还是 IM，本质都是一个 Agent 聚合所有能力，通过工具路由切换模式。

### 市场空白

| 维度 | 单 Agent 产品的局限 | 多 Agent 能解决的 |
|------|---------------------|------------------|
| **角色混淆** | 同一个 Agent 同时做规划、执行、验证 | 各司其职，不冲突 |
| **长任务可见性** | "黑盒"跑完才出结果 | Plan 出方案 → Executor 执行 → Chat 汇报，每一步可见 |
| **并行能力** | 一次只能干一件事 | Plan 调研的同时 Executor 可以开工 |
| **定制深度** | 改行为 = 改 Prompt | 新增一个 Agent = 定义一个角色 |
| **团队协作** | 单人工具 | 天然支持异步协作 |

## 二、StarChain 的定位

> **The Multi-Agent Coding Platform.**
> 一个拥有多角色智能体的开发团队，随时待命。

### 一句话定位

**"你的 AI 开发团队。不是一个助手，是一个团队。"**

### 与竞品的差异化

```
                   单 Agent（所有竞品）
                        │
                        │  StarChain 的护城河
                        ▼
               ┌────────────────────┐
               │   多 Agent 协作      │
               │                    │
               │  Chat ─→ Plan ─→ Executor
               │         ↓             │
               │      Reviewer ←───────┘
               │                    │
               │   + 自定义 Agent     │
               └────────────────────┘
                        │
                        ▼
               ┌────────────────────┐
               │   多渠道分发         │
               │   Feishu · CLI · Web│
               └────────────────────┘
```

### 目标用户画像

| 用户 | 场景 | 为什么选 StarChain |
|------|------|-------------------|
| **独立开发者** | 一个人在飞书里管理项目 | 手机发需求 → Agent 团队干活 → 手机收结果 |
| **小团队** | 团队用飞书协作开发 | 在飞书群里直接分配任务给不同 Agent |
| **技术负责人** | 需要多个 Specialist Agent | 自定义一个 Code Review Agent 专门审代码 |
| **微创业** | 低成本做项目 | 不装 IDE、不配环境，手机就能驱动开发 |

### 内置 Agent 角色（v1）

| 角色 | 职责 | 权限 |
|------|------|------|
| **Chat** | 用户对话界面、意图识别、结果汇报 | 无工具 |
| **Plan** | 需求分析、方案调研、输出执行计划 | 只读（read_file, search_files, web_search） |
| **Executor** | 按方案编码、执行命令、交付结果 | 全套工具 |
| **Reviewer** (v0.6) | 审查 Executor 的交付物质量 | 只读 + 代码分析 |

### Agent 角色生态（v2+）

| 角色 | 定位 | 对标人类团队 |
|------|------|------------|
| **Architect** | 架构设计 | 架构师 |
| **Tester** | 自动化测试 | QA 工程师 |
| **Doc Writer** | 文档撰写 | 技术文档 |
| **DevOps** | 部署运维 | 运维工程师 |
| **Product** | 需求梳理 | 产品经理 |

## 四、产品阶段路线图

### MVP 阶段（当前 — v0.3~v0.5）

**定位：** 一个能用的多 Agent Coding Bot。

| 版本 | 主题 | 交付能力 | 对标水平 |
|------|------|----------|----------|
| v0.3 | 配置系统 | YAML 配置 Agent 角色、工具、模型 | 基础可定制 |
| v0.4 | 流式 + 记忆 | 长任务可见、跨会话连贯 | 体验达标 |
| v0.5 | 生产化 | 飞书通道稳定、部署文档齐全 | 可用级 |

**用户看到的：**
> 在飞书里跟 Chat 聊天 → Chat 把需求转给 Plan → Plan 出方案 → Executor 干活 → Chat 汇报结果
> 改 YAML 就能加新工具、新 Agent、换模型

### 成长阶段（v0.6~v0.8）

**定位：** 可编排的 Agent 团队。

| 版本 | 主题 | 交付能力 | 对标水平 |
|------|------|----------|----------|
| v0.6 | 复杂拓扑 | 星型路由、监督型拓扑、Reviewer 角色 | 编排能力 |
| v0.7 | 长期记忆 | RAG 知识库、项目级记忆 | 上下文即团队 |
| v0.8 | 多渠道 | CLI 终端 + Web Dashboard | 渠道覆盖 |

**用户看到的：**
> 创建一个项目 → 指定 Agent 团队组成（Chat + Plan + Executor + Reviewer）
> 发需求 → Plan 出方案 → Executor 编码 → Reviewer 审查 → 改完汇报
> 飞书、终端、网页三端同步

### 成熟阶段（v1.0+）

**定位：** 多 Agent 协作开发平台。

| 版本 | 主题 | 交付能力 |
|------|------|----------|
| v1.0 | 平台化 | Agent Registry（社区共享 Agent 角色）、Plugin Marketplace |
| v1.1 | 企业级 | RBAC、审计日志、自部署、SSO |
| v1.2 | IDE 集成 | VS Code 扩展、JetBrains 插件 |
| v1.3 | 智能编排 | Agent 自动发现、自适应拓扑、任务并行 |

## 五、StarChain vs 竞品 对标表

| 维度 | Claude Code | Codex CLI | Cline | Hermes | **StarChain (目标)** |
|------|------------|-----------|-------|--------|-------------------|
| **Agent 数量** | 1 | 1 | 1 | 3 (Profile) | **无限** (配置定义) |
| **协作方式** | 无 | 无 | 无 | 异步 DB | **原生 Handoff** |
| **渠道** | CLI / VS Code | CLI | VS Code | IM / CLI / Email | **IM + CLI + Web + IDE** |
| **工具生态** | 内置 | 内置 | MCP | 60+ 内置 | **内置 + 自定义插件 + MCP** |
| **定制性** | Prompt | Prompt | Prompt+规则 | YAML 配置 | **YAML + 自定义 Agent + 插件** |
| **记忆** | 会话内 | 会话内 | 会话内 | 有限 | **跨会话 Profile + RAG** |
| **移动端** | ❌ | ❌ | ❌ | ⚠️ 仅 IM | **✅ 飞书原生 + 流式** |
| **开源** | ❌ | ❌ | ✅ | ✅ | **✅** |
| **团队协作** | ❌ 单人 | ❌ 单人 | ❌ 单人 | ⚠️ 单用户 | **✅ 多用户 + Agent 团队** |

### StarChain 的独特卖点

> **"Not a copilot. A crew."**
> 不是副驾驶，是一个机组。

| 卖点 | 说明 |
|------|------|
| 🧠 **多脑并行** | 不同 Agent 同时处理不同任务 |
| 👁 **全程可见** | 规划→执行→审查，每一步都有输出 |
| 🎯 **分工明确** | 每个 Agent 只做擅长的事，不出圈 |
| 🔧 **深度可定制** | 加 Agent = YAML 加一段配置 |
| 📱 **移动原生** | 手机发需求，Agent 团队干活，手机收结果 |

## 七、风险与对策

| 风险 | 概率 | 影响 | 对策 |
|------|------|------|------|
| 多 Agent 手延迟高 | 高 | 体验差 | v0.4 流式响应 + Agent 间通信优化 |
| 飞书 API 限流 | 中 | 消息丢 | v0.5 限流处理 + 队列缓冲 |
| 用户不会配 YAML | 中 | 门槛高 | v0.8 Web Dashboard 可视化配置 |
| 单 Agent 就能做好的事 | 中 | 过度设计 | 每个版本做减法：复杂拓扑放 v2 |
| 模型成本翻倍（多 Agent = 多调用） | 高 | 用户不买单 | 可控 token 预算 + Agent 级成本追踪 |

## 八、总结

**StarChain 不是另一个 Chat Bot 套壳。**

它是一个以"多 Agent 协作"为核心产品 identity 的 Coding Agent 平台。在单 Agent 产品拥挤的市场里，多 Agent 既是技术差异，也是产品差异。

> **Claude Code / Codex / Cline 帮你干活。**
> **StarChain 给你一个团队。**

先做到 v0.5 验证基础能力，再逐步加 Agent 生态、多渠道、平台化。
