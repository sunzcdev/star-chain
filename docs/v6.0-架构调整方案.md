# v6.0 — 架构调整方案：生产级多 Agent Coding Agent

> 目标：基于现有 v5.0 架构，调整为生产级、可定制、支持飞书移动端的多 Agent 协作 Coding Agent。

## 1. 现状评估

### v5.0 架构总览

```
Feishu ──→ FeishuAdapter ──→ AgentRuntime ──→ Chat → Plan → Executor → Tools
```

| 层 | 现状 | 评价 |
|----|------|------|
| **通道层** | FeishuAdapter (lark-oapi WebSocket) | 基本可用，API 细节需实测验证，缺流式、缺媒体 |
| **Runtime** | AgentRuntime (Session + Runner.run()) | 够用，但无配置体系 |
| **Agent 层** | 三 Agent 硬编码 (Chat/Plan/Executor) | 不可扩展，角色/工具/指令均固定 |
| **工具层** | 13 个工具 (Code/Web/Skill/MCP) | 功能完整，但无自定义注册机制 |
| **记忆** | 每会话 JSON 历史（50 条上限） | 仅会话内，跨会话无记忆 |

### 满足目标的差距分析

| 目标三要素 | 当前 | 差距 |
|-----------|------|------|
| ① Coding Agent | ✅ Code 工具完备 | 缺自定义工具注册、缺长时间任务反馈 |
| ② 多智能体协作 | ✅ 三 Agent handoff | 角色不可扩展、拓扑不可配置 |
| ③ 飞书 Channel + 移动端 | ⚠️ 通道能通 | 缺流式响应、缺图片/文件消息、移动端 UX 未优化 |

## 2. 核心命题讨论

### 2.1 是否支持可扩展 Agent？

**结论：v1 支持「配置式 Agent 扩展」，v2 支持「动态 Agent 扩展」。**

**需求分析：**
用户需要的不只是写死三个 Agent，而是：
- 能在 YAML 里定义新 Agent（角色名、Instructions、工具列表、handoff 目标）
- 能调整现有 Agent 的行为（修改 Prompt、增减工具）
- 不需要改源码

**设计方案：**
```
# config/agents.yaml
agents:
  chat:
    instructions: "你是聊天助手..."
    tools: []
    handoffs: [plan]
  plan:
    instructions: "你是方案规划师..."
    tools: [read_file, search_files, web_search]
    handoffs: [executor, chat]
  executor:
    instructions: "你是执行者..."
    tools: [all]
    handoffs: [chat]
  # 用户可在此扩展第四个 Agent
  # code_reviewer:
  #   instructions: "..."
  #   tools: [read_file, search_files]
  #   handoffs: [chat, executor]
```

启动时 `build_agent_topology()` 不再硬编码，改为从 YAML 读取拓扑定义，动态构建 Agent 实例和 handoff 链。

### 2.2 是否支持记忆？

**结论：v1 支持「跨会话持久记忆」，v2 支持「结构化长期记忆」。**

**需求分析：**
当前 SessionContext 只在单次会话内保留 50 条消息历史。作为 coding agent，用户可能：
- 同一个项目多次对话需要上下文连贯
- 记住用户的偏好（模型选择、编程风格、常用工具）
- 记住项目特定的约定

**v1 方案：跨会话持久记忆（Key-Value 存储）**

```
~/.star-chain/memory/
  └── <user_id>/
      ├── sessions/          # 原有会话历史
      │   ├── <session_id_1>.json
      │   └── <session_id_2>.json
      └── profile.json       # 用户偏好（跨会话）
          # {
          #   "preferred_model": "deepseek-v4-flash",
          #   "preferred_language": "Python",
          #   "project_context": "agent-channel 项目",
          #   "preferences": { ... }
          # }
```

每个会话结束时：
1. 提取关键信息（用户偏好、项目上下文、常用命令）
2. 更新 `profile.json`
3. 下次会话启动时注入 profile 作为 system prompt 上下文

**v2 方案：结构化长期记忆**
- 向量数据库（ChromaDB 轻量级）
- RAG 检索：将项目代码、对话摘要、决策记录向量化
- 支持语义检索（"之前那个数据库 Schema 是怎么设计的来着？"）

### 2.3 多 Agent 的组织形式？

**结论：v1 支持「可配置线性链」，v2 支持「复杂拓扑」。**

**可能的组织形式：**

| 形式 | 描述 | 适用场景 | v1/v2 |
|------|------|---------|-------|
| **线性链** | A → B → C → A | 简单的分工流水线，当前模式 | ✅ v1 |
| **星型（Router）** | Chat → 多个 specialist Agent | 多领域专家编排 | ❌ v2 |
| **监督型** | Manager Agent 管理多个 worker | 复杂任务分解+进度追踪 | ❌ v2 |
| **黑板型** | 共享工作区，Agent 独立读写 | 大型项目的异步协作 | ❌ v2 |
| **Swarm** | Agent 自由发现 + handoff | 探索型任务 | ❌ v2 |

**v1 策略：**
- 保留「线性链」作为基础拓扑
- 通过 YAML 配置可以增减链上的 Agent 数量（最小 2 个，最大不限）
- 每个 Agent 可配置 handoff 目标和工具集

**v2 策略：**
- 支持「星型路由」——Chat Agent 根据意图路由到不同 Specialist Agent
- 支持「监督型」——一个 Manager Agent 管理子 Agent 的执行进度
- 拓扑定义从 YAML 扩展到可编程 DSL

## 3. v1 架构调整方案

### 3.1 目标架构

```
Feishu ──→ FeishuAdapter ──→ AgentRuntime ──→ 动态 Agent 拓扑
                        │            │              │
                    StreamAdapter    Config      AgentBuilder
                     (流式响应)      (YAML)    (从 YAML 构建)
                         │            │              │
                    ┌────┴────┐  agents.yaml    tools.yaml
                    │ Media   │  models.yaml
                    │ 消息     │  star-chain.yaml
                    └─────────┘
```

### 3.2 新增模块

#### 模块 A：配置系统 (`config/`)

**文件结构：**
```
~/.star-chain/
├── config/
│   ├── star-chain.yaml      # 主配置文件
│   ├── agents.yaml          # Agent 角色定义
│   ├── tools.yaml           # 工具开关与自定义
│   └── models.yaml          # LLM 模型配置
├── sessions/                # 会话历史（现有）
├── memory/                  # 跨会话记忆（新增）
│   └── <user_id>/
│       └── profile.json
├── logs/
└── mcp_servers.json         # MCP Server 配置（现有）
```

**star-chain.yaml 主配置：**
```yaml
# 星链主配置
channel:
  type: feishu
  app_id: "${FEISHU_APP_ID}"
  app_secret: "${FEISHU_APP_SECRET}"
  stream_enabled: true        # 流式响应
  media_support: true         # 媒体消息

runtime:
  default_model: deepseek-v4-flash
  max_turns: 30
  api_timeout: 60
  session_timeout: 120

memory:
  enabled: true
  type: profile              # v1: key-value profile
  # v2: vector  # 二期
```

**agents.yaml 定义：**
```yaml
agents:
  chat:
    enabled: true
    name: "Chat"
    instructions: |
      你是聊天助手和入口网关...
    model: deepseek-v4-flash     # 可为每个 Agent 指定不同模型
    tools: []
    handoffs:
      - target: plan
        description: "用户有明确需求时 handoff"
        
  plan:
    enabled: true
    name: "Plan"
    instructions: |
      你是方案规划师...
    model: deepseek-v4-flash
    tools:
      - read_file
      - search_files
      - web_search
    handoffs:
      - target: executor
        description: "方案就绪后 handoff"
      - target: chat
        description: "需求不清晰时 handoff 回 Chat"
        
  executor:
    enabled: true
    name: "Executor"
    instructions: |
      你是执行者...
    model: deepseek-v4-flash
    tools: [all]                  # 允许通配符
    handoffs:
      - target: chat
        description: "执行完毕 handoff 回 Chat"
```

**tools.yaml 定义：**
```yaml
tools:
  # 内置工具开关
  code:
    read_file: true
    write_file: true
    patch: true
    search_files: true
    terminal: true
    execute_code: true
  web:
    search: true
    extract: true
  skill:
    run_skill: false              # 默认关闭，按需开启
    call_claude_code: false
    call_open_code: false
  mcp:
    enabled: true
    servers:
      - my-mcp-server

  # 自定义工具注册（新增）
  custom:
    - name: my_tool
      module: ~/.star-chain/custom_tools/my_tool.py
      description: "我的自定义工具"
```

#### 模块 B：自定义工具注册机制

**需求：** 用户写一个 Python 函数 → 配置注册 → Agent 自动发现使用

**接口规范：**
```python
# ~/.star-chain/custom_tools/my_tool.py
from agents import function_tool

@function_tool
def my_deploy_tool(service_name: str) -> str:
    """部署指定服务到测试环境。
    
    Args:
        service_name: 服务名称
    Returns:
        部署结果
    """
    # ... 业务逻辑
    return f"部署成功: {service_name}"
```

注册后，在 `tools.yaml` 中声明：
```yaml
custom:
  - name: my_deploy_tool
    module: ~/.star-chain/custom_tools/my_tool.py
```

AgentRuntime 启动时扫描 `custom_tools/` 目录，动态 import + `function_tool` 注册。

#### 模块 C：流式响应适配

**需求：** Coding Agent 任务可能执行 10-60 秒，飞书需要分段反馈。

**方案：**
```
FeishuAdapter.send_streaming(user_id, message_id, chunks)
  1. 先发一条"正在分析..."
  2. Runner.run_streamed() 产出 token
  3. 每 N 个 token / 每完成一步 → Feishu 更新消息
  4. 最终结果替换为完整回复
```

飞书 Channel 支持 `channel.update_message()` API（消息编辑替换）。

**AgentRuntime.handle_message 改为流式：**
```python
async def handle_message_stream(
    self, user_id: str, text: str
) -> AsyncGenerator[str, None]:
    session = self._get_or_create_session(user_id)
    session.add_user_message(text)
    
    result = Runner.run_streamed(
        self._entry_agent,
        input=session.history,
        max_turns=self._max_turns,
        run_config=self._run_config,
    )
    
    async for event in result.stream_events():
        if event.type == "raw_response_event" and event.data.delta:
            yield event.data.delta  # 逐 token 产出
    
    session.add_assistant_message(result.final_output)
    session.save()
    yield result.final_output  # 最终结果
```

#### 模块 D：记忆系统（v1）

**跨会话 Profile：**
```
~/.star-chain/memory/<user_id>/profile.json
```

**数据采集规则：**
- 每次对话结束后提取：用户提到的项目名、偏好的工具、常用命令
- 格式为简单的 key-value
- 下次对话开始时，profile 内容注入 Chat Agent 的 system prompt

**提取策略：** 用 LLM 对对话摘要做一次轻量提取（单次调用），不复杂。

### 3.3 不动的部分

| 模块 | 理由 |
|------|------|
| `channel_adapter.py` 接口 | 已验证抽象正确 |
| `session.py` 会话管理 | 功能完整 |
| `account_store.py` 凭证管理 | 功能完整 |
| 现有 13 个工具的实现 | 功能完整，只加配置开关 |
| `run.py` 入口逻辑 | 只需注入 Config，结构不变 |

## 5. v1 vs v2 边界

### v1 "切"的原则

1. **只做必须的**：配置、自定义、流式、记忆 — 没有这些不能叫"生产级可定制"
2. **不做超前设计**：复杂拓扑（星型/监督型/RAG 记忆）放 v2
3. **骨架不动**：不改 channel_adapter 接口、不改 session 模型、不改现有 tool 实现
4. **测试先行**：F-12 端到端测试 P0，跑通了再部署

### 判断一个功能是 v1 还是 v2 的标准

```
这个功能不做，用户能用吗？
├─ 能 → v2（锦上添花）
└─ 不能 → v1（生存底线）
```

| 功能 | 不做能跑吗？ | 归期 |
|------|------------|------|
| YAML 配置 | ❌ 不能 — 用户改不了模型/工具 | v1 |
| 自定义工具 | ❌ 不能 — coding agent 不开放工具等于废 | v1 |
| 流式响应 | ⚠️ 能但体验差 — 10s+ 任务用户干等 | v1 |
| 跨会话记忆 | ⚠️ 能但每次重来 — 记不住项目上下文 | v1 |
| 媒体消息 | ✅ 能 — 纯文字 Bot 也能用 | v2 优先 |
| RAG 记忆 | ✅ 能 — profile 够用了 | v2 |
| 复杂拓扑 | ✅ 能 — 线性链满足 80% 场景 | v2 |
